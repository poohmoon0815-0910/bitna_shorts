# 유튜브 호기심빛나 쇼츠5편 제작 워크플로우

사용자가 웹대시보드(`http://127.0.0.1:5173/`)에서 **1~3단계**를 완료한 후 **"유튜브 호기심빛나 쇼츠5편"** 제작을 요청하면 아래 순서와 규칙을 정확히 따라 5편의 쇼츠를 제작한다.

## 1. 시작 전 확인
- 사용자가 웹대시보드(`http://127.0.0.1:5173/`)에서 **1~3단계**를 마쳤는지 확인한다.
- **풀오토(1~3단계 대행) 모드**: 사용자가 1~3단계를 직접 하지 않고 AI에게 전권 위임(풀오토)을 요청한 경우, `shorts-team/02_planner_factchecker.md`의 **풀오토 주제 선정 가드레일**(인체 2 + 우주 2 + 일상 과학 1 비율, 금지 주제 제외, 3초 후킹 기준, `outputs/` 중복 방지)에 따라 AI가 1~3단계부터 직접 실행한다.
- 대시보드에 생성된 **4단계 기획방향/추천 주제** 중 무조건 순번대로 하거나 1번을 고집하지 않고, **'호기심빛나' 채널 방향성(과학·인체·우주·호기심 지식 탐구)과 유튜브 업로드 성과에 가장 도움이 되는 주제**를 AI가 직접 선별·판단하여 진행한다.
- 브라우저 자동화 시작 직후(1~2분 내) MCP/브라우저 권한 팝업이 뜨면 사용자가 허용할 수 있도록 안내하고, 이후 웹창 내부의 일반 선택/확인 팝업은 작업 흐름에 맞게 처리한다.

## 2. 쇼츠 1편당 제작 순서 (AI 자율 검수 · 선별 진행)
선별된 기획방향에 대해 새 프로젝트 또는 해당 기획방향 선택 상태로 아래 단계를 진행한다:

1. **5단계(대본 초안 2개 생성), AI 비교 검수 선택 및 사실 검증(Fact-Check)**
   - **무조건 `DRAFT_A`(1번)를 선택하는 기존 규칙은 폐기한다.**
   - 대본 초안 2개(`DRAFT_A`, `DRAFT_B`)가 생성되면 두 초안을 모두 읽고 비교 검수하여, **'호기심빛나' 채널 방향성, 첫 3초 후킹 강도, 숫자·체감 비유 몰입도, 클레이 3D 시각화 적합성, 유튜브 알고리즘 성과에 가장 유리한 초안**을 AI가 직접 판단해 선택한다. (둘 다 방향이 어긋났거나 부족하면 피드백을 넣어 재생성한 뒤 선택한다.)
   - **사실 검증(필수 — 대본 확정 및 TTS 생성 전)**: 선택한 초안 대본의 숫자·단위·과학/역사적 사실·비유(예: 빛의 속도 vs 우주선 속도, 지구 질량, 혈압/혈류량, 관측 오차, 연도 등)를 **반드시 1차 검증(필요 시 웹 검색 포함)** 한다.
   - 과장·단위 혼동·명백한 사실 오류가 있으면 **대본 확정 및 TTS(성우 음성) 생성 전에 먼저 자연스럽고 정확한 표현으로 수정·반영**한 뒤 대본을 확정한다. (TTS가 먼저 생성된 뒤 수정하면 성우 음성과 자막·씬 타임스탬프를 반드시 다시 생성/정렬해야 함.)
2. **제목 설정**
   - 선택한 기획방향의 제목을 그대로 가져오되, **제목 앞의 숫자/번호(`1.`, `01_`, `1)` 등)는 반드시 제거**한다.
   - 긴 제목이 영상 상단에서 양옆으로 잘리지 않고 깔끔하게 표시되는지 확인한다.
3. **7단계(음성 생성 / TTS)**
   - 음성 생성을 완료한다.
4. **이미지 매칭 및 Google Flow 이미지/동영상 생성**
   - **전체 매칭: 전체/일부 OFF** 상태로 설정한다.
   - **고유 이미지 8~10장 유지 + 동적 연출 필수 규칙**: 편당 고유 이미지 수는 8~10장으로 유지하되, 단조로움을 막기 위해 Remotion 렌더링 시 ① **모든 씬에 동적 카메라 워크(미세한 줌인/줌아웃 또는 패닝)를 기본 적용**하고, ② **2~2.5초마다 화면 전환 또는 핵심 키워드 강조 애니메이션 등 시각적 변화를 반드시 부여**한다. (기존 '장당 약 4.0~4.8초 노출' 규칙은 폐기)
   - **사운드 디자인(BGM & SFX) 필수**: 초반 3초 훅 진입 시와 체감형 반전이 터지는 핵심 타이밍에 효과음(SFX)을 배치하고, 주제 분위기에 맞는 BGM을 나레이션을 방해하지 않는 **-18dB ~ -22dB**로 믹싱한다.
   - (참고) (인접한 동일 맥락의 짧은 씬들은 같은 이미지를 공유하거나 씬을 묶어 시각적 여유와 기억도를 높인다.)
   - **Google Flow(`https://flow.google.com/`)** 에서 `browser` 서브에이전트를 통해 씬별 이미지(또는 동영상)를 생성한다.
   - **Google Flow 기본 모델 설정**: 이미지 생성 시 모델 선택에서 **`Nano Banana Pro`** 를 기본 선택하고(`이미지`, `9:16`, `x1`, `0 크레딧` 확인), 만약 일일 Pro 한도에 도달한 경우에만 남은 씬을 `Nano Banana 2`로 이어서 생성한다.
   - **Google 정책 위반 방지(필수)**: Google Flow는 프롬프트 텍스트뿐만 아니라 **업로드한 시작 프레임 이미지 자체의 얼굴·인물 유사도**까지 검사한다. 따라서 `start_image_prompt`, `video_prompt` 등 모든 프롬프트에 **실존 인물·유명인 이름**(예: `Elon Musk`, `Musk` 등)을 절대 직접 넣지 않으며, 이미지 역시 실존 인물을 닮지 않은 **오리지널 캐릭터**(`a cute original clay scientist character`, `the tiny clay figurine` 등 일반 명사·역할 표현)로 생성해 사용한다.
   - **속도/안정성 규칙**: 자동화 감지나 CAPTCHA가 걸리지 않도록 한 번에 무리하지 말고 4~8개 씬 단위 소량 배치로 **천천히** 생성하고, 각 이미지를 **`1K 원본 크기`** 로 다운로드한다.
5. **최종 렌더링, 자막 싱크 및 주제 적합도 검수**
   - 다운로드한 씬 이미지들을 적용해 최종 영상(`final.mp4`)을 렌더링한다.
   - 렌더링이 끝나면 대시보드 호환용 `final.mp4`와 별개로, **프로젝트 폴더 안에 영상 제목 그대로의 파일명(`<제목>.mp4`, Windows 파일명 금지문자 `? * : " < > | / \` 제거)**으로도 사본을 반드시 생성해 둔다.
   - 자막(`raw_stt.json` ↔ `scene_data.json`) 1:1 싱크 일치 여부를 확인한다.
   - **주제 적합도 검수(`topic-audit`)**: 완성된 영상이 '호기심빛나' 메인 채널 주제(과학·인체·우주·호기심)에 맞는지 검수한다. **`메인 채널 적합`** 판정 시에만 메인 채널 업로드 대상에 포함하고, **`주제 불일치(off_topic)`** 또는 **`일부 수정 권장(needs_rework)`** 판정 시에는 메인 채널에 바로 올리지 않고 별도 분류하여 활용 가이드(서브/실험 채널, 릴스·틱톡 테스트, 인트로 재가공 등)를 보고한다.
6. **다음 편으로 이동**
   - 대시보드에서 **5단계 대본 초안 선택** 단계로 돌아가 다음 기획방향(2번 → 3번 → 4번 → 5번)을 선택하고 1~5번 과정을 반복해 총 **5편**을 완성한다.

## 3. 최종 정리 및 유튜브 업로드 규칙
- 5편 제작이 모두 끝나면 `c:\shorts-v2\outputs\완성된_쇼츠_5편_<날짜YYMMDD>\` 폴더(예: `완성된_쇼츠_5편_261117`)에 완성된 `final.mp4` 5편을 **앞 번호와 언더바(`_`)를 뺀 제목명(`<제목>.mp4`)** 으로 복사해 모아둔다.
- **유튜브 무인 자동 파일 첨부 및 예약 업로드(필수)**:
  - 사용자에게 파일을 직접 복사·드래그하거나 파일 선택 창에서 골라 달라고 요청하지 **않는다**.
  - `browser` 서브에이전트가 유튜브 스튜디오(`https://studio.youtube.com/`)에서 **만들기 → 동영상 업로드**를 연 뒤, OS 파일 탐색기가 뜨는 `파일 선택` 버튼을 누르지 말고 DOM 내 `<input type="file">` 요소(예: `input[name="Filedata"]` 또는 `input[type="file"]`)를 찾아 `upload_file` 도구로 로컬 `.mp4` 파일 경로를 **직접 첨부**한다. (숨김 처리로 스냅샷에 보이지 않으면 `evaluate_script`로 해당 `<input type="file">`을 잠시 표시한 뒤 `upload_file`로 첨부한다.)
  - **유튜브 업로드 시 해시태그(필수)**: 제목은 해시태그 없이 깔끔하게 유지하고, **설명(Description)란에 해당 영상 주제에 알맞은 핵심 해시태그 4~5개**(`#쇼츠 #Shorts` + 주제별 키워드 2~3개)를 반드시 포함한다.
  - **예약 업로드(`publishAt`) 사전 완료 규칙(필수)**: 예약 업로드는 한국 기준 **하루 2편(권장 낮 12:00 / 오후 6:00)** 순차 예약을 원칙으로 하며, **예약 공개 시각(`publishAt`)보다 최소 1시간 30분 이전에는 업로드가 완료되도록 스케줄링**한다.
  - **업로드 직후 재생목록(`playlistId`) 추가 & 첫 댓글 API 자동 작성(필수)**: 업로드가 끝나면 즉시 지정된 **재생목록(`playlistId`)에 해당 영상을 자동 추가**하고, **영상 대본에 맞는 첫 댓글을 API로 자동 작성**해 둔다.
  - 5편 모두 파일 첨부부터 예약 확정까지 자동으로 완료한 뒤 결과를 보고한다.
  - **고정 댓글 등록, 상단 고정 및 완료 로그/예외 처리(필수)**: 영상이 공개되는 시점(매일 18:00)에 맞춰 시청자 참여를 유도하는 밸런스·질문형 고정 댓글을 채널 명의로 작성(또는 API로 작성된 첫 댓글 확인)하고, 브라우저 자동화로 **상단 고정(Pin)** 및 **하트(Heart)** 처리를 완료한다. 완료 시 완료 로그(`handoff_03_qa_upload.md`)에 반드시 **`댓글 고정 완료`**라고 기록을 남기며, **로그인 풀림 등으로 실패했을 때만 대표님께 알림을 주는 예외 처리**를 적용한다.
- 최종 보고 시 각 편별 제목, 씬 수, 원본 `final.mp4` 경로, 정리본 경로, 유튜브 예약 일시를 안내한다.

## 4. 추가 기능 / 변경 사항 기록
- **쇼츠 제작팀 총괄 실장 직할 3인 정예 체제 연동**: 이 워크플로우는 루트 `AGENTS.md` 및 `c:\shorts-v2\shorts-team\`(02 기획/팩트체크 · 03 비주얼/렌더링 · 04 검수/업로드, 총괄은 ⚡ 총괄 실장) 역할 구조와 연동하여 실행한다. 각 단계가 끝날 때 프로젝트 폴더에 `handoff_01_plan_factcheck.md` → `handoff_02_visual_render.md` → `handoff_03_qa_upload.md` 파일을 남겨 다음 역할로 정확히 인계한다.
- 사용자가 향후 이 작업에 추가하고 싶은 기능이나 수정 사항을 알려주면, 이 파일(`c:\shorts-v2\.agents\skills\youtube-hogisimbitna-shorts-5\SKILL.md`)에 함께 업데이트하여 영구 기억한다.
- **비서/멘토 소통 원칙(필수)**:
  - 선택지가 있을 때 사용자에게 모호하게 되묻지 말고, 각 선택지의 장단점을 짚어준 뒤 **"지금 상황에서는 이 방법이 가장 안전하고 좋습니다. 이렇게 가시죠!"**라고 **명확한 추천 방향 1가지를 먼저 제시**해 사용자가 확신을 갖고 실행할 수 있도록 돕는다.
  - 다음 업로드까지 **10시간 전후로 여유 시간이 남거나** 사용자가 망설일 때는, **전담 비서 겸 선생님**으로서 따뜻하지만 분명하게 다음 할 일과 방향을 먼저 제시하고 실행을 이끌어 의욕을 북돋워 준다. (사용자가 겁이 많고 신중한 편이므로, 리스크를 먼저 줄여주고 "제가 옆에서 챙길 테니 걱정 마시고 이대로 가시죠"라고 안심시킨다.)
